# OmniHub 프로젝트 구현 최종 보고서

## 1. 개요
본 프로젝트는 기존의 랜덤 생성 데이터를 사용하는 Mock 기반의 OmniHub를 **실제 백엔드 API와 연동**하고, **결정론적이고 설명 가능한(Explainable) 지식 그래프 UX**로 업그레이드하는 것을 목표로 진행되었습니다.

## 2. 주요 구현 내용

### 2.1 백엔드 실데이터 연동 (Backend Integration)
- **API 연동 (`dataService.ts`)**:
  - 기존 Mock 함수를 모두 제거하고 백엔드 엔드포인트와 연동했습니다.
  - `fetchInitialData()`: `/api/initial-data` (초기 문서/개념 로드)
  - `chat()`: `/api/chat` (AI 질의응답 및 인용 정보 수신)
  - `searchEvidence()`: `/api/graph/evidence` (근거 기반 서브그래프 생성)
  - `getDocChunks()`: `/api/docs/{id}/chunks` (문서 상세 근거 청크 조회)
- **데이터 정규화 (Normalization)**:
  - 백엔드의 다양한 응답 포맷(스네이크 케이스 등)을 프론트엔드 표준 타입(`DocRecord`, `ConceptNode`)으로 변환하는 견고한 Layer를 구축하여 안정성을 확보했습니다.
- **예외 처리 (Fallback)**:
  - API 서버가 오프라인일 때 개발/데모가 가능하도록 Fallback 데이터를 자동으로 로드하는 로직을 추가했습니다.

### 2.2 의미 기반 그래프 시각화 (Meaningful Graph Visualization)
- **결정론적 레이아웃 (Deterministic Layout)**:
  - 기존의 랜덤 좌표 생성을 제거하고, 노드 ID 기반의 해시 함수를 도입하여 **새로고침 해도 그래프 형태가 유지**되도록 개선했습니다.
  - 이를 통해 사용자가 위치를 기억하고 탐색하는 경험을 강화했습니다.
- **의미 기반 연결 (Semantic Edges)**:
  - 단순 무작위 연결이 아닌, 실제 데이터 관계에 기반한 엣지를 생성합니다.
  - **Doc-Concept**: 문서가 해당 개념 태그를 포함할 때 연결.
  - **Concept-Concept**: 두 개념이 다수의 문서에서 공동 등장(Co-occurrence)할 때 연결.
  - **Doc-Doc**: 두 문서가 다수의 공통 개념을 공유할 때 연결.

### 2.3 설명 가능한 UX (Explainable UX)
- **증거(Evidence) 탭 추가**:
  - `DocDetailDrawer`에 **Evidence & Chunks** 탭을 신설했습니다.
  - 문서의 주요 내용이 담긴 Chunk 데이터를 시각적으로 나열하고, 보안 레벨과 페이지 정보를 표시합니다.
- **인용구 추적**:
  - 채팅 답변의 인용구([1], [2])를 클릭하면, 그래프에서 해당 문서가 강조되고 Drawer가 열리며 구체적인 근거 문구(Snippet)를 확인할 수 있습니다.
- **시각적 포커싱**:
  - 트리나 채팅에서 문서를 선택하면 그래프 카메라가 부드럽게 해당 노드로 이동(Pan/Zoom)하여 문맥을 놓치지 않도록 했습니다.

### 2.4 성능 및 안정성 (Performance & Stability)
- **노드 제한 (Node Cap)**:
  - 그래프가 지나치게 복잡해지는 것을 막기 위해 상위 중요 개념 및 최신 문서 위주로 렌더링하도록 제한을 두었습니다.
- **빈 상태 처리 (Empty State)**:
  - 데이터가 없거나 로딩 중일 때 사용자에게 명확한 상태 메시지를 보여주는 UI를 추가했습니다.

## 3. 남은 과제 및 제언
1. **대용량 최적화**: 문서가 수만 건 이상일 경우 클라이언트 사이드 렌더링 한계를 극복하기 위해 WebGL 기반 렌더러(예: PixiJS, Cosmos) 도입 고려 필요.
2. **실시간 편집**: 문서의 태그나 승인 상태를 변경했을 때 백엔드에 즉시 반영하는 `PATCH` API 연동 고도화 필요.
